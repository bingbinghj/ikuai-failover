# 故障转移服务

服务根据爱快原生线路检测、连续失败阈值、恢复阈值和切换间隔协调物理主备出口。主线路、备用线路和保留的默认 WAN 从爱快实际接口中选择，三者应为不同接口。DNS 和代理服务继续由部署方的现有网络提供。

线路名称读取爱快系统概览的 `homepage/show`、`wan_stat` 信息，根据返回的运营商代码显示名称；缺失时回退到 WAN 接口名。名称读取在独立循环中运行，不阻止线路检测和故障转移，代码与公开模板不写死部署方的运营商或实际网络地址。

## 部署与首次配置

- 管理页面和 API 共用容器 TCP 19002，镜像为 `ghcr.io/bingbinghj/ikuai-failover:latest`，目前提供 linux/amd64 构建。
- 默认 Compose 使用 `./data:/etc/ikuai-failover` 和 `./state:/var/lib/ikuai-failover`，配置目录与状态目录可写。空配置目录首次启动自动生成 `data/config.yml`，已有配置内容保留。
- 公开模板只提供通用占位信息。连接地址、凭据及实际选择结果保存到本地部署配置，不提交到公共仓库。
- Web 登录账号为 `webui.user/pass`，和爱快连接账号独立。缺少其中任一字段时，启动过程会为缺失字段生成随机值并写回配置；已填写字段保留。首次登录从本地 `config.yml` 读取这两个字段。
- `IKB_WEBUI_USER/PASS` 可以覆盖 Web 登录配置，非空环境变量去除首尾空白后生效。普通登录有效期7天；勾选记住密码后默认保持登录30天，并在本浏览器加密保存用于回填的密码。状态卷保存签名密钥，退出清除当前Cookie，修改网页登录凭据并重启后旧会话失效。
- 爱快连接字段为 `ikuai.base_url`、`ikuai.username/password`，也支持非空 `IKUAI_FAILOVER_USERNAME/PASSWORD` 环境变量覆盖。连接账号密码允许留空，此时控制台可用，线路轮询和策略写入等待配置，`/readyz` 返回未就绪。
- 控制台使用可视化分类表单维护配置，当前页面不提供完整YAML文本编辑入口。接口、规则、IPv6实例通过爱快读取和下拉选择，ID与名称自动保存；通知按需添加。实际配置保存在部署目录的`data/config.yml`。
- 需要重启的修改保存后显示提示及重启按钮，按钮只重启本服务，通过容器重启策略恢复，不重启路由器。修改网页登录账号密码后需要用新凭据登录；留空的网页登录字段在下次启动时随机生成并保存。
- 新生成配置遵循目录权限继承与 umask；保存已有配置保留其 POSIX 权限。自定义 SMB/NFSv4 ACL 由部署方的存储权限管理，已有严格权限不会自动放宽。
- 页面保存使用版本比对、文件锁和原子写入。配置被其他方式修改时拒绝覆盖，需重新加载后保存。已填写完整的配置可使用只读挂载，但初始化或页面保存要求配置目录可写。
- 自动应用默认关闭，仅生成计划；确认选择的主备规则与待执行变化后再开启。页面保存前校验格式和字段，并通过版本比对避免覆盖外部修改。

首次配置顺序：

1. 填写爱快连接地址和账号密码，读取爱快选项。可使用尚未保存的连接信息只读获取接口与规则。
2. 从下拉列表选择主线路、备用线路和保留的默认 WAN；后者应对应爱快当前唯一默认路由。
3. 按需添加“防回环、运营商分流、域名分流”，选择相应主备规则。备用候选按接口和流量匹配条件筛选，不手填 ID 或规则名称。
4. 需要 IPv6 时，从爱快选择现有 WAN 和 LAN 实例；需要通知时，添加使用的渠道并填写接收目标和凭据。
5. 保存并按提示重启，确认观察模式的计划没有阻止原因，再开启自动应用。

读取失败、列表不完整或原选项已不存在时，页面提示刷新，不会凭空创建接口或静默替换已保存的规则。未配置的实例和规则需要先在爱快创建，再刷新选项。

主机管理入口、默认网关和 DNS 应使用部署方实际配置。容器沿用宿主机出站路由，修改 DHCP 记录不会自动修改手工配置的主机路由。

## 策略与 IPv6

- 页面中的“防回环”对应爱快五元组规则，“运营商分流”和“域名分流”分别选择相应规则。选择结果包含内部 ID、规则名称和接口，供服务确认身份，用户无需手填。
- 规则名称来自爱快的 `tagname`，备注来自 `comment`，它们是不同字段。页面显示实际名称和备注，选择后自动保存需要的名称。
- 成对规则要求选择相同流量，分别绑定主备出口。服务先启用目标出口再关闭原出口，只协调启停并保留匹配条件；名称、接口或选择器与配置不符时停止应用。
- 可视化配置使用成对域名分流，不再增加单条“域名出口绑定”配置入口。旧配置中的 `domain_rules` 仍保留文本兼容；域名解析或 DDNS 更新继续由部署方已有服务处理。
- 检测结果来自爱快线路检测。失败和恢复次数按成功读取的采样累计；备用线路不正常时不会切过去。`stable_hold_ms` 表示距上次成功切换的最短间隔，不是连续恢复正常的时间。
- 写入使用快照、写前比较、写后验证及持久化日志。爱快尚未证实提供原子条件更新，外部程序在比较与写入之间改动同一规则仍可能产生竞争；冲突时保留日志，不盲目覆盖。
- 失败时恢复已写规则；重启后检查未完成日志，不覆盖外部程序的新修改。状态目录只允许一个服务进程持有。
- IPv6 WAN 与 LAN 实例从爱快实际列表选择，实例 ID、名称和 LAN 接口自动保存。当前协调模型要求单 WAN 槽和自动 DHCP/PD；不受支持的实例会显示原因，不能作为可选项。
- 迁移 IPv6 出口后等待全局地址、有效 PD 和来自目标 PD 的 LAN 前缀；超时或缺少 PD 时独立报告并回滚 IPv6，IPv4 协调继续运行。
- `configuration_verified` 表示配置符合支持的模型；`operational_verified` 表示地址、PD 和 LAN 前缀检查已满足要求。出口地址存在不能单独证明 PD 可用。
- 规则确认通过读回结果完成。服务不在每次正常切换时默认重启路由器或旁路由网络。

## 接口与运行

- 页面使用 MoviePilot v3 的主题配色和交互方式，主题切换、通知铃铛与头像位于右上角。头像菜单可以退出登录或确认重启本服务；相关刷新和配置操作放在各自卡片中。
- 通知中心提供未读、失败、搜索和展开详情；标记已读仅改变当前浏览器的阅读状态，不删除待投递通知或影响重试。
- 运行日志保存在状态目录的 `logs/` 下，单份最大5 MiB，最多10份（当前日志加9份历史日志）。达到上限时自动轮转，重启后继续保留。页面支持选择文件、筛选和暂停刷新，已移除下载入口。
- 日志记录运行事件和错误，输出前清理连接密码、通知凭据等已知敏感值；日志目录仍应留在部署环境中。磁盘日志不可写时保留控制台输出，不因此停止线路协调。

- `/status` 提供线路状态、地址、待应用规则、IPv6 检查结果和通知统计；`/notifications` 提供最近事件及投递结果。
- `/logs/files`、`/logs/tail` 和 `/logs/download` 提供受登录保护的日志文件、末尾记录及下载，只接受本服务管理的日志文件名。
- `/settings/ikuai` 的 GET/POST 用于读取和保存爱快连接配置；实际变更记录 `configuration_saved` 事件。
- `/settings/config` 的 GET/POST 用于完整配置编辑；`/system/restart` 请求本服务平滑退出，需配合容器自动重启策略。
- `/settings/options` 的 GET 使用运行连接读取选项，POST 使用编辑中的连接信息只读获取接口、规则及 IPv6 实例；该操作不保存配置或修改路由器。
- 状态、通知和设置接口均受当前 Web 登录保护。`/healthz` 表示进程健康，`/readyz` 表示当前 IPv4 出口健康且协调没有阻止原因，两者公开。
- `--dry-run` 强制只读路由器操作；`--once` 输出一次计划；`--check` 校验配置，不连接路由器或绑定服务端口。
- Vue 前端由 Docker 使用 `npm ci`、类型检查和 Vite 构建，静态文件位于 `/usr/share/ikuai-failover/web`。
- 原版 `ikuai-bypass` 如果同时更新受管理规则，需要协调规则所有权和更新时机，避免覆盖已经选定的出口。分流原则见 [分流配置指南](routing-review.md)。
- [通知配置](notifications.md)支持事件筛选、去重、重试和重启后继续投递；凭据仅保存在本地部署配置或环境变量中。
- GitHub Actions 在 push 后构建镜像，构建成功直接发布 Packages；`latest` 仅默认分支更新，并同时发布 SHA 标签。pull request 只构建镜像。

镜像包含 AGPL-3.0 许可证和源码来源标签，来源见 [项目总览](../README.md)。
